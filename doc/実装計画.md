# オフライン対応・ローカルSQLite実装計画

既存のモック（HTML/CSS/JS SPA）を **Electron アプリ**にラップし、  
**better-sqlite3** によって本物のSQLiteでデータをローカル永続保存します。

---

## 方針

- 既存の画面構成は維持しつつ、会社名を「司商事」に統一する
- モックの文字・アイコンは視認性を優先して大きくする
- `app.js` のインメモリ配列操作を → **Electron IPC 経由の SQLite 操作**に置き換え
- データは `%APPDATA%\kanjo-daijin\kanjo-daijin.db` に自動生成・保存
- `npm run dev` でアプリ起動、完全オフライン動作

### Electron メインプロセス

#### [NEW] `main.js`

- `ipcMain.handle` で以下のCRUDハンドラを実装：
  - `db:getAccounts` / `db:saveAccount`
  - `db:getTransactions` / `db:saveTransaction` / `db:deleteTransaction`
  - `db:getJournals`
  - `db:getMonthlySummary`
  - `db:initialize`（スキーマ作成のみ。サンプルデータは投入しない）

#### [NEW] `preload.js`
- `contextBridge.exposeInMainWorld('db', {...})` で以下を公開：

```js
window.db.getAccounts()
window.db.saveTransaction(data)
window.db.deleteTransaction(id)
window.db.getJournals(filters)
window.db.getMonthlySummary(year, month)
// ... 他
```

### データベーススキーマ

#### [NEW] `db/schema.sql`

```sql
-- 勘定科目マスタ
CREATE TABLE IF NOT EXISTS accounts (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  code          TEXT NOT NULL UNIQUE,
  name          TEXT NOT NULL,
  category      TEXT NOT NULL,  -- 資産/負債/収益/費用
  display_order INTEGER NOT NULL DEFAULT 0,
  is_active     INTEGER NOT NULL DEFAULT 1,
  created_at    TEXT NOT NULL,
  updated_at    TEXT NOT NULL
);

-- 取引データ
CREATE TABLE IF NOT EXISTS transactions (
  id               INTEGER PRIMARY KEY AUTOINCREMENT,
  transaction_date TEXT NOT NULL,
  transaction_type TEXT NOT NULL,
  amount           INTEGER NOT NULL CHECK (amount > 0), -- 円単位
  payment_method   TEXT NOT NULL,
  account_id       INTEGER NOT NULL REFERENCES accounts(id),
  partner_name     TEXT,
  description      TEXT,
  memo             TEXT,
  is_deleted       INTEGER NOT NULL DEFAULT 0,
  created_at       TEXT NOT NULL,
  updated_at       TEXT NOT NULL
);

-- 仕訳データ
CREATE TABLE IF NOT EXISTS journals (
  id                 INTEGER PRIMARY KEY AUTOINCREMENT,
  transaction_id     INTEGER NOT NULL REFERENCES transactions(id),
  journal_date       TEXT NOT NULL,
  debit_account_id   INTEGER NOT NULL REFERENCES accounts(id),
  debit_amount       INTEGER NOT NULL CHECK (debit_amount > 0), -- 円単位
  credit_account_id  INTEGER NOT NULL REFERENCES accounts(id),
  credit_amount      INTEGER NOT NULL CHECK (credit_amount > 0), -- 円単位
  description        TEXT,
  is_deleted         INTEGER NOT NULL DEFAULT 0,
  created_at         TEXT NOT NULL,
  updated_at         TEXT NOT NULL
);
```

## 検証計画

### 手動検証
1. `npm install` → `npm run dev` でアプリが起動すること
2. 勘定科目を登録 → 取引を入力 → アプリを完全終了 → 再起動してデータが保持されていること
3. PC をネットワークから切断した状態で全操作が動作すること
4. `%APPDATA%\kanjo-daijin\kanjo-daijin.db` ファイルが生成されていること

## 実装上の確定事項

### 金額・整合性

- 金額は円単位の `INTEGER` で保存し、`REAL` は使用しない。
- 取引の登録・更新・論理削除、ならびに対応する仕訳の再生成・更新は、すべて単一のSQLiteトランザクション内で完結させる。
- `journals` テーブルを仕訳の保存先とする。取引を編集した際は、元取引から仕訳を再生成して更新する。

### Electronセキュリティ

- `BrowserWindow` は `contextIsolation: true`、`nodeIntegration: false` を設定する。
- レンダラープロセスには、preloadの `contextBridge` を介して必要最小限のDB操作だけを公開する。

### 依存関係と初期化

- `better-sqlite3` はElectron向けネイティブモジュールとしてビルドする。必要に応じて `electron-rebuild` を開発依存関係に追加し、`npm install` 後に再ビルドするスクリプトを用意する。
- 初回起動時はテーブル作成のみ実施し、勘定科目・取引・仕訳のサンプルデータは一切投入しない。
